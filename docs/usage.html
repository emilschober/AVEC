AVEC

Usage

AVEC assesses each exonic variant for exon skipping automatically in under 30 seconds. The user should look at the literature search to identify existing ASO strategies, and verify the individual guideline checks. The guideline checks include ‘no pathogenic splice site variants’. By default, this is always assessed as true, even if pathogenic splice site variants are found. The user should verify the splice site variants cause complete or in-frame exon skipping and then override the guideline check to false, therefore turning the exon skipping assessment into ‘not eligible’. A similar approach is taken for important domains: the user may manually override this guideline check to turn the assessment into ‘not eligible’.

For other strategies (knockdown, wildtype-upregulation and splice correction), additional user input is required. For assessment of wildtype upregulation and knockdown, the user is asked to select the pathomechanism of the variant and can choose from Loss of function (LoF), Gain of function (GoF) and Dominant negative (DN). The available literature search in the pathomechanism section of AVEC can aid with this. The mode of inheritance is derived from the ClinGen consortium and is gene- not variant- specific. This means that in instances where different modes of inheritance exist for a given gene, special attention must be paid.

For splicing correction assessment, the tool requires confirmation of experimental validation of missplicing via qPCR or RNA-Seq. AVEC automatically checks SpliceVarDB and SSCVDB for experimental validation of the variant. If the variant is not listed in SpliceVarDB, the user can choose to state whether there is experimental validation for or against splicing effects. Afterwards, the user is asked to decide whether there are pathogenic effects independent of splicing: Splice-altering exonic variants may lead to an altered function of the protein independent of splicing, for example a nonsense pathogenic variant.

AVEC will categorize eligibility according to the guidelines and give an explanation why the category is chosen (eligible, likely eligible, unlikely eligible, not eligible, unable to assess). Additionally, it provides links to the underlying databases to increase transparency and aid in manual verification of the results. Experienced assessors can choose to override the information provided by the underlying data sources, changing the assessment accordingly. The assessment can be saved as a .html file.
