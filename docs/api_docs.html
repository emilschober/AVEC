AVEC API documentation

The AVEC API provides programmatic access to the variant assessment tool. You can retrieve the same detailed analysis available through the web interface via a simple POST request.

Endpoint

The base URL for the API endpoint is:

https://avec.uni-koeln.de/api/v1/assess

Request

The API accepts POST requests with a JSON body containing a single required key.

  • Key: query
  • Description: The variant to assess in a recognized HGVS-like format (at most 200 characters).
  • Examples: NM_018026.4:c.607C>T, PACS1 c.607C>T, NC_000007.14:g.117639961C>T

The API runs the automatic assessment only. The inputs the web interface asks for (mechanism of action, mode-of-inheritance override, splice validation, exonic pathogenicity, guideline overrides) cannot be passed. Knockdown and WT Upregulation depend on the mechanism of action, so the API assesses them for every mechanism (gain of function, loss of function and dominant negative) and lists the results side by side in mechanism_assessments.

An assessment queries several external services and can take up to about a minute, so allow a generous client timeout.

Example usage (cURL)

curl -X POST "https://avec.uni-koeln.de/api/v1/assess" \
     -H "Content-Type: application/json" \
     -d '{"query": "NM_018026.4:c.607C>T"}'

Response

The API returns a JSON object containing the full assessment, structured identically to the data used by the web interface.

  • On success (HTTP 200), the response contains:
    • summary: gene-level information (gene, transcript, protein effect, ClinGen mode of inheritance and dosage sensitivity, rCNV scores, literature links).
    • assessments: one entry per applicable strategy, e.g. Exon_Skipping, Splice_Switching, N1C_Registry_Check, N1C_Assessed_Variants or General_Assessment. Exon_Skipping is an array: the single-exon result, followed by double-exon options when the exon is out of frame. Each result has a classification and a reason (N1C entries contain HTML), and most have checks, each with passed, original_passed and overridden.
    • mechanism_assessments: the mechanism-dependent strategies for each mechanism of action, keyed GoF, LoF and DN. Each holds the Knockdown, WT_Upregulation and N1C_Gene_Knockdown results that apply to that mechanism and the gene's mode of inheritance, in the same shape as the entries in assessments. An empty object means no mechanism-dependent strategy applies (for example loss of function in a recessive gene). An established ASO in the N1C registry ends the assessment early, so this key is then absent.
    • transcript_info (only when the query names a transcript) and alternative_result (the assessment on the MANE Select/canonical transcript, when it differs from the requested one).
    • visualization: the genome browser tracks shown in the web interface.
  • On failure, the response is a JSON object with an error key and an HTTP status code: 400 (missing, invalid or too long query), 404 (the variant could not be assessed, e.g. not found by VEP), 413 (request body larger than 64 KB) or 500 (server error).
